# tp81 依赖台账与版本核查平台

一个本地小工具：把各个项目用到的依赖集中登记起来。页面上先建项目，再往项目下面登记依赖名称、版本、许可、责任人与状态；同一个依赖被两个项目用到时，版本高低一眼能比出来。依赖名写得不合规矩、版本不是三段数字、同一个项目里重复登记同一个依赖，保存时当场就会指出来。

依赖之间互相需要的关系也能登记：哪条依赖需要哪些其它依赖、最低要什么版本。页面上看得出每条依赖被谁需要、它自己又需要谁；从某一条依赖出发还能把它一路往下需要的完整清单按层展开。指向没登记过的依赖、最低版本写法不成立、绕成一圈（自己需要自己、两条互相需要、多条绕回起点）的关系，保存时当场拒绝并写清问题出在哪。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5081>

端口固定为 `5081`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，新建登记时会把它带进责任人
2. 项目区列出项目名称、负责人、说明与这个项目下已经登记了多少条依赖；可以新增项目，也可以改名、换负责人、删除
3. 依赖登记区顶部可以按项目、状态、许可筛选，再按依赖名、责任人或者备注搜索，右上角刷新按钮重新拉取一次
4. 点新建登记，选好所属项目，填上依赖名称、版本，按需要补许可、责任人、状态与备注；列表里点编辑会把这条登记回填到表单
5. 依赖登记列表的「需要」「被需要」两列直接看得出每条依赖需要谁、被谁需要，鼠标放上去能看到对方属于哪个项目、要求的最低版本
6. 依赖关系区在登记区下面：选好「哪条依赖」需要「哪条」、填上最低版本就能登记；关系不成立会当场拒绝并写清原因。下面的完整需要清单可以从任意一条依赖出发，把它一路往下需要的依赖按层展开
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除项目与删除登记都会先确认

项目下面还挂着依赖登记时不允许删除项目，页面上会写清还剩多少条、例如哪几条，先处理这些登记再删。删除一条依赖登记时，它牵扯到的关系（它需要别人的、别人需要它的）会一起清掉。

## 登记口径

- 依赖名称以小写字母或数字开头，可以用小写字母、数字、点、下划线、短横线与斜线，最长 60 个字符；带范围的写法例如 `@types/node` 也按这个口径登记
- 版本写成三段数字，例如 `2.7.18`，需要时可以带一段预发布后缀，例如 `5.0.10-rc.1`
- 许可按实际名称填写，例如 `MIT`、`Apache-2.0`、`BSD-3-Clause`；还没确认的可以留空，列表里会显示成未填
- 责任人可以留空，表示这条依赖还没有定人
- 状态只有三种：在用、待升、已弃用
- 备注用来写为什么用这个版本、有没有待办，最长 200 个字符
- 同一个项目下不允许出现同名的依赖，同一个依赖在不同项目里各登记各的、互不覆盖

## 关系口径

- 关系登记在两条依赖之间：「哪条依赖」需要「哪条」，可以跨项目；同一条从到对只允许登记一次
- 每条关系都要填最低版本，写法与依赖版本同一个口径：三段数字，需要时可以带一段预发布后缀
- 三种情况当场拒绝：指向没有登记过的依赖（报错里带出没登记的登记号）、最低版本写法不成立、绕成一圈
- 环形包括自己需要自己、两条互相需要、三条以上绕回起点；拒绝时会把环上的依赖按顺序写清，例如 `t-d → t-a → t-b → t-d`
- 完整需要清单按层展开：第 1 层是直接需要的，第 2 层是第 1 层那些依赖需要的，依此类推；同一条依赖只出现一次，保留它最早出现的那一层，清单里每条都标明是第几层、由谁从上一层带进来、要求的最低版本

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "projects": [...], "deps": [...], "relations": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径                     | 说明                                             |
| ------ | ------------------------ | ------------------------------------------------ |
| GET    | /api/health              | 服务状态检查                                     |
| GET    | /api/projects            | 项目清单，附带每个项目的依赖条数                 |
| POST   | /api/projects            | 新增项目                                         |
| PATCH  | /api/projects/:id        | 修改项目的名称、负责人或说明                     |
| DELETE | /api/projects/:id        | 删除项目                                         |
| GET    | /api/deps                | 依赖登记列表，支持按项目、状态、许可筛选与关键词搜索 |
| POST   | /api/deps                | 新增依赖登记                                     |
| GET    | /api/deps/:id            | 查看单条依赖登记                                 |
| PATCH  | /api/deps/:id            | 修改依赖登记                                     |
| DELETE | /api/deps/:id            | 删除依赖登记，相关的依赖关系一起清掉             |
| GET    | /api/deps/:id/closure    | 从一条依赖出发，按层展开它一路往下需要的完整清单 |
| GET    | /api/relations           | 依赖关系清单，附带全部依赖的简要清单             |
| POST   | /api/relations           | 新增依赖关系（哪条需要哪条、最低版本）           |
| DELETE | /api/relations/:id       | 删除依赖关系                                     |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
