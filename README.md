# tp81 依赖台账与版本核查平台

一个本地小工具：把各个项目用到的依赖集中登记起来。页面上先建项目，再往项目下面登记依赖名称、版本、许可、责任人与状态；同一个依赖被两个项目用到时，版本高低一眼能比出来。依赖名写得不合规矩、版本不是三段数字、同一个项目里重复登记同一个依赖，保存时当场就会指出来。

依赖之间谁需要谁也能登记：每条关系写上需要哪条依赖、最低版本要求多少，依赖登记表上直接看得出每条依赖需要谁、被谁需要；从任意一条依赖出发，可以把它一路往下需要的完整清单按层展开。指向没登记的依赖、最低版本写法不成立、绕成一圈（自己需要自己、两条互相需要、多条绕回起点）的关系都会被当场拒绝，成环时会把环上的依赖逐个点名。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5081>

端口固定为 `5081`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，新建登记时会把它带进责任人
2. 项目区列出项目名称、负责人、说明与这个项目下已经登记了多少条依赖；可以新增项目，也可以改名、换负责人、删除
3. 依赖登记区顶部可以按项目、状态、许可筛选，再按依赖名、责任人或者备注搜索，右上角刷新按钮重新拉取一次
4. 点新建登记，选好所属项目，填上依赖名称、版本，按需要补许可、责任人、状态与备注；列表里点编辑会把这条登记回填到表单
5. 依赖登记表上的"需要谁"与"被谁需要"两列，直接看得出每条依赖自己需要谁、又被谁需要
6. 关系区在依赖登记区下面：选好哪条依赖、需要哪条依赖、填上最低版本就能新增关系；下面的完整需要清单可以选一条依赖，把它一路往下需要的依赖按层展开，每条都标着是第几层、由谁带进来的
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除项目、删除登记与删除关系都会先确认

项目下面还挂着依赖登记时不允许删除项目，页面上会写清还剩多少条、例如哪几条，先处理这些登记再删。删除依赖登记时，挂在它身上的关系（它需要的、需要它的）会一起删掉，删除提示里会写清删掉了几条。

## 登记口径

- 依赖名称以小写字母或数字开头，可以用小写字母、数字、点、下划线、短横线与斜线，最长 60 个字符；带范围的写法例如 `@types/node` 也按这个口径登记
- 版本写成三段数字，例如 `2.7.18`，需要时可以带一段预发布后缀，例如 `5.0.10-rc.1`
- 许可按实际名称填写，例如 `MIT`、`Apache-2.0`、`BSD-3-Clause`；还没确认的可以留空，列表里会显示成未填
- 责任人可以留空，表示这条依赖还没有定人
- 状态只有三种：在用、待升、已弃用
- 备注用来写为什么用这个版本、有没有待办，最长 200 个字符
- 同一个项目下不允许出现同名的依赖，同一个依赖在不同项目里各登记各的、互不覆盖

## 关系口径

- 关系登记在两条依赖登记之间：哪条依赖需要哪条依赖，带上最低版本要求；同一个依赖名出现在多个项目里时，关系精确到具体项目下的那条登记
- 最低版本要求必填，写法与登记版本同口径：三段数字，需要时可以带一段预发布后缀
- 同一对依赖之间的关系只登记一次
- 关系不允许绕成一圈：自己需要自己、两条互相需要、多条绕回起点都会被当场拒绝，提示里会把环上的依赖逐个列出来
- 完整需要清单按层展开：直接需要的是第 1 层，第 1 层需要的是第 2 层，以此类推；同一条依赖只出现一次，保留它最早出现的那一层，每条都带上有哪一层、由谁带入
- 删除依赖登记时，挂在它身上的关系一起删掉

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "projects": [...], "deps": [...], "links": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。载入时会整理结构：指向不存在项目的登记、指向不存在登记的关系、自己需要自己、重复以及会绕成一圈的关系，一律丢掉。

## 接口一览

| 方法   | 路径                   | 说明                                             |
| ------ | ---------------------- | ------------------------------------------------ |
| GET    | /api/health            | 服务状态检查                                     |
| GET    | /api/projects          | 项目清单，附带每个项目的依赖条数                 |
| POST   | /api/projects          | 新增项目                                         |
| PATCH  | /api/projects/:id      | 修改项目的名称、负责人或说明                     |
| DELETE | /api/projects/:id      | 删除项目                                         |
| GET    | /api/deps              | 依赖登记列表，支持按项目、状态、许可筛选与关键词搜索 |
| POST   | /api/deps              | 新增依赖登记                                     |
| GET    | /api/deps/:id          | 查看单条依赖登记                                 |
| PATCH  | /api/deps/:id          | 修改依赖登记                                     |
| DELETE | /api/deps/:id          | 删除依赖登记，挂在它身上的关系一起删掉           |
| GET    | /api/deps/:id/closure  | 从这条登记出发一路往下需要的完整清单，按层展开   |
| GET    | /api/links             | 依赖关系清单，附带全量依赖（供页面下拉框使用）   |
| POST   | /api/links             | 新增依赖关系                                     |
| DELETE | /api/links/:id         | 删除依赖关系                                     |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
